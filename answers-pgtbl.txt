

## **题目1：Which other xv6 system call(s) could be made faster using this shared page? Explain how.**

### **可优化的系统调用**

1. **`uptime()`**
   - **理由**：系统运行时间是全局的、只读的、随时间递增的数据。
   - **优化方式**：在共享页中存储 `ticks` 变量的值，内核在每个时钟中断时更新它。用户态直接读取，无需系统调用。

2. **`getuid()` / `geteuid()`**（如果 xv6 实现用户权限）
   - **理由**：用户ID在进程生命周期内通常不变。
   - **优化方式**：在共享页中存储进程的用户ID、组ID等信息。

3. **`getcwd()`**（获取当前工作目录）
   - **理由**：当前目录在 `chdir()` 调用之间保持不变。
   - **优化方式**：在共享页中存储当前目录的 inode 号或路径哈希，但需要注意目录可能被删除。

4. **`times()`**（获取进程时间信息）
   - **理由**：进程的 CPU 时间统计信息相对稳定，且用户态只读。
   - **优化方式**：在共享页中存储进程的 `utime`、`stime`、`cutime`、`cstime` 等字段，内核在进程切换时更新。

### **局限性分析**
- **可变数据问题**：如 `uptime()` 需要内核定期更新共享页，存在用户读到稍旧值的可能。
- **安全性问题**：只能暴露**只读**数据，任何可写数据都不能放入共享页。
- **空间限制**：一个页面（4KB）能容纳的数据有限，需要选择最频繁调用的系统调用数据。

## **题目2：Explain the output of vmprint in terms of Fig 3-4 from the text.**

### **页表结构解析**
```
page table 0x0000000087f6e000
 ..0: pte 0x0000000021fda801 pa 0x0000000087f6a000
 .. ..0: pte 0x0000000021fda401 pa 0x0000000087f6b000
 .. .. ..0: pte 0x0000000021fdac1f pa 0x0000000087f6b000
 .. .. ..1: pte 0x0000000021fda00f pa 0x0000000087f6b000
 .. .. ..2: pte 0x0000000021fd9c1f pa 0x0000000087f6b000
 ..255: pte 0x0000000021fdb401 pa 0x0000000087f6d000
 .. ..511: pte 0x0000000021fdb001 pa 0x0000000087f6c000
 .. .. ..509: pte 0x0000000021fdd813 pa 0x0000000087f6b000
 .. .. ..510: pte 0x0000000021fddc07 pa 0x0000000087f6b000
 .. .. ..511: pte 0x0000000020001c0b pa 0x0000000080007000
```

### **对照图3-4的层级结构**
xv6 使用三级页表（RISC-V Sv39）：
- **第1级**：根页表（Page Directory，顶级）
- **第2级**：中间页表（Page Table，中间级）
- **第3级**：叶页表（最终物理页映射）

**输出格式解析：**
- `..0:` 表示第1级页表的第0项
- `.. ..0:` 表示第2级页表的第0项
- `.. .. ..0:` 表示第3级（叶）页表的第0项，映射到用户虚拟地址 `0x0`

### **具体问题解答**

#### **1. What does page 0 contain?**
- **虚拟页0**（用户地址 `0x0`）映射到物理页 `0x87f6b000`
- **权限位**：`0x1fdac1f` = `PTE_V | PTE_R | PTE_W | PTE_X | PTE_U | PTE_A | PTE_D | ...`
- **内容**：这是**用户进程的代码/数据起始页**，通常包含程序的入口代码（`_entry`）和初始数据。

#### **2. What is in page 2?**
- **虚拟页2**（用户地址 `0x2000`）映射到物理页 `0x87f67000`
- **权限位**：`0x1fd9c1f`，同样具有读、写、执行、用户访问权限
- **内容**：很可能是**用户程序的后续代码段或数据段**。在典型的 xv6 用户程序中：
  - 页0：入口代码和初始数据
  - 页2：更多的程序代码或堆区域

#### **3. When running in user mode, could the process read/write the memory mapped by page 1?**
**不能。** 原因如下：
- 从输出中看，**没有显示虚拟页1（地址0x1000）的映射**。
- 这意味着页表项 **PTE_V 位为0**，即该页未映射。
- 在用户模式下访问未映射的地址会触发**页面错误异常**（page fault）。
- **设计原因**：xv6 通常将虚拟地址0x0作为起始，0x1000可能被留作**保护页**（guard page），用于检测栈溢出或空指针解引用。

#### **4. What does the third to last page contain?**
**第三到最后一项（倒数第三项）对应的是 TRAPFRAME 页。**

具体分析：
- 输出的最后三行对应虚拟地址高端的特殊映射：
  ```
  .. .. ..509: pte 0x0000000021fdd813 pa 0x0000000087f76000  ← 倒数第三
  .. .. ..510: pte 0x0000000021fddc07 pa 0x0000000087f77000  ← 倒数第二（TRAMPOLINE）
  .. .. ..511: pte 0x0000000020001c0b pa 0x0000000080007000  ← 最后一项
  ```
- **虚拟地址**：根据 RISC-V Sv39，最后512项对应虚拟地址高端（`0xFFFFFFXX...`）
- **509项**：权限位 `0x21fdd813` = `PTE_V | PTE_R | PTE_W | PTE_U`（可读、可写、用户态）
- **物理地址**：`0x87f76000`
- **这是 TRAPFRAME 页**：存储用户进程陷入内核时的寄存器上下文，用于内核态和用户态切换时保存/恢复寄存器状态。

### **权限位解码示例**
- `PTE_V` (0x01)：条目有效
- `PTE_R` (0x02)：可读
- `PTE_W` (0x04)：可写  
- `PTE_X` (0x08)：可执行
- `PTE_U` (0x10)：用户态可访问
- `PTE_A` (0x40)：已访问
- `PTE_D` (0x80)：已修改（脏页）

### **xv6 用户地址空间布局总结**
根据输出和 xv6 设计：
1. **低地址区**（如0x0, 0x2000）：用户代码和数据
2. **未映射页**（如0x1000）：保护页，捕获错误
3. **高端固定映射**：
   - `TRAPFRAME`：陷入帧，用户-内核切换用
   - `TRAMPOLINE`：蹦床页，包含陷入/返回代码
   - 其他内核映射（如共享的 `USYSCALL` 页）
