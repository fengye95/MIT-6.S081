这个问题要求你找出**为什么双线程会出现缺失键而单线程不会**，并描述导致键缺失的事件序列。

---

## **答案要点**

### **1. 根本原因：没有适当的锁保护**

当两个线程同时向**同一个哈希桶**插入时，如果没有正确的锁保护，会出现**竞争条件**，导致一个插入覆盖另一个。

### **2. 导致键缺失的具体事件序列**

```
假设：哈希表，桶#1初始为空，两个线程都要插入到桶#1

时间线：
线程A：                    线程B：
1. 计算key1的哈希 → 桶#1
2. 遍历桶#1链表，没找到key1
3. 创建新entry e1
   e1->key = key1
   e1->value = value1
4.                         计算key2的哈希 → 桶#1
5.                         遍历桶#1链表（看到空链表）
6.                         创建新entry e2
                           e2->key = key2
                           e2->value = value2
7. 执行 e1->next = bucket[1]
    （将e1插入链表头）
8.                         执行 e2->next = bucket[1]
                           （将e2插入链表头，覆盖e1的插入！）
9.                         完成，bucket[1] = e2
10. 完成，bucket[1] = e1（覆盖e2！）

结果：bucket[1]最终指向e1，e2完全丢失！
      key2在哈希表中不存在，尽管put()调用成功返回。
```

### **3. 可视化表示**
```
初始： bucket[1] → NULL

线程A插入key1后（如果单独运行）：
bucket[1] → e1(key1) → NULL

线程B插入key2后（如果单独运行）：
bucket[1] → e2(key2) → e1(key1) → NULL

但并发执行时可能：
时间点8: bucket[1] → e2(key2) → NULL
时间点10: bucket[1] → e1(key1) → NULL  ← e2被覆盖丢失！
```

### **4. 为什么单线程没问题？**
单线程按顺序执行：
- 插入key1完成 → 链表：e1
- 插入key2完成 → 链表：e2→e1
没有并发修改，所以不会丢失。

### **5. 解决方案**
为每个桶加锁：
```c
put(key, value) {
    int b = hash(key) % NBUCKET;
    acquire(&lock[b]);  // 保护整个桶
    // 查找和插入
    release(&lock[b]);
}
```
这样，同一时间只有一个线程能修改一个桶，防止了上述竞争。

---

## **总结**
缺失键的原因是**并发插入同一个哈希桶时的竞争条件**，导致一个插入操作被另一个覆盖。这展示了为什么并发数据结构需要适当的同步机制。
